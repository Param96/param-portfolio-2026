## What explains the reported noindex results

No unintended public `noindex` directive could be reproduced in the current repository or live responses. All six public landing pages and the one currently published blog article return HTTP 200, `robots: index, follow`, and their own canonical URLs. No public `X-Robots-Tag: noindex` header was present. A Googlebot user agent and ordinary browser responses were checked.

- Next.js `notFound()`: automatically injects `noindex` for missing resources; kept.
- `src/proxy.ts` (formerly middleware): Clerk authentication and visitor tracking; does not add a public `noindex` directive.
- Sanity SEO overrides contain titles, descriptions, and images; there is no CMS `noindex` field or SEO plugin supplying a hidden public restriction.

## Confirmed fixes

All changes in this section are **fixed locally but awaiting deployment**, and verified in a production build.

| Issue | Change and verification |
| --- | --- |
| Headings and featured-article links absent from initial HTML | Enabled server rendering for the existing meadow heroes, including contact's separate import. Preserved their styling and browser WebGL behavior. All seven public pages now include an initial H1. |
| Child metadata replaced nested social defaults | Explicit website/article Open Graph settings and large-image Twitter cards on public routes. Homepage social title and description are explicit. CMS article title/description overrides are honored. |
| Homepage canonical inherited by auth and error pages | Removed the root layout's fallback canonical. Every public route still supplies its own. Auth, admin, and missing pages have no inherited homepage canonical. |
| Delayed missing-article detection could emit a streamed 200 | Missing articles call `notFound()` during metadata generation; metadata resolves before streaming for every user agent. Unknown blog/research URLs return genuine 404 responses. |
| Static sitemap dates fabricated on every regeneration | Removed static-route `lastModified`; dynamic entries use real CMS `_updatedAt` only when valid. |
| Sitemap could become stale or inherit editor context | Explicit published perspective, no stega, origin CMS reads, 60-second revalidation. CMS failure propagates rather than silently returning a partial sitemap. |
| Inconsistent article eligibility | Shared title/slug/publication-date filter for blog/research listing, detail, and sitemap queries. Drafts and release versions are excluded from the sitemap by Sanity's published perspective; future-dated documents are excluded. Build parameters explicitly use published data. |
| Duplicate or invalid sitemap entries | Deduplicate URLs and reject malformed slugs. Only existing landing, blog, and research routes are generated. Current output contains exactly seven URLs. |
| A second generator could restore nonexistent URLs | Retired the static generator that wrote a conflicting `public/sitemap.xml` and advertised `/about`, `/notes`, `/resume`, project detail pages, and arbitrary CMS pages without implemented routes. It now exits with guidance to use the App Router endpoint. |
| Exact sensitive route paths missed by robots.txt | One consistent wildcard-agent group now covers exact sensitive paths and descendants. Public pages and rendering assets remain crawlable. Robots rules remain separate from authentication. |
| Trailing-slash normalization disabled | Removed `skipTrailingSlashRedirect`; `/blog/` permanently redirects to `/blog`, consistent with its canonical. |
| Published research articles could lack listing links | Added a server-rendered list to `/research` when real published research documents exist. No articles or dates were fabricated. Current CMS has no published research detail entries. |
| Optional analytics could crash articles | Missing PostHog credentials now disable the optional server capture instead of throwing during article rendering. Both supported environment-key names are accepted. |
| Deprecated Next.js middleware convention | Renamed `src/middleware.ts` to `src/proxy.ts` with the same authentication and tracking logic. Protected-route behavior passes verification. |
| Removed lint command | Replaced `next lint` with the official Next.js ESLint configuration and a compatible ESLint version. Existing lint debt is reported separately below. |

Production origin remains **`https://parampatel.in`**, as confirmed by live redirects and existing configuration. Switching to www would contradict the current deployment. `SITE_URL` is a fixed production constant; neither `NEXT_PUBLIC_SITE_URL` nor `VERCEL_URL` can introduce a development/preview canonical. Public metadata contains no local or Vercel preview origin. No Vercel project configuration file is checked in; DNS, deployment protection, and preview response headers could not be inspected through the rejected account credential.
